# 工作区标签页滚动恢复性能优化计划

## 1. 背景

工作区标签页已经具备以下能力：

- 从子 Agent 面板跳转到文件标签页后，可以返回上一个标签页。
- 返回子 Agent 面板时，可以恢复滚动位置。
- 可以恢复 `visibleTurnCount` 和每一轮过程区的展开状态。
- 页面刷新后不恢复旧位置，关闭标签页后不恢复旧位置。

当前实现没有保活完整标签页，也不会缓存 DOM、iframe、图片或 React 组件树。主要缓存两类数据：

1. 工作区标签页的滚动现场。
2. 子会话时间线和过程区状态，用于返回时立即重建内容。

正常使用场景下性能开销很小。潜在风险主要来自：

- 子会话时间线缓存没有容量上限。
- 恢复大量轮次时，每个 turn 都会触发一次快照写入。
- 快速滚动时会频繁扫描锚点并读取 DOM 位置。
- 流式输出时，时间线状态可能高频写入缓存。
- 用户展开大量轮次后，复杂 DOM 布局本身会成为主要瓶颈。

本计划只处理这些可量化的性能问题，不改变用户已经确认的返回与滚动恢复行为。

## 2. 目标

### 2.1 功能目标

- “子 Agent 滚到任意位置 -> 打开文件 -> 返回”仍然恢复到原位置。
- 用户原本在底部时，返回后继续跟底。
- 用户展开过更早轮次时，返回后保持相同展开范围。
- 每一轮过程区的展开/折叠状态保持稳定。
- 子会话短缓存被淘汰时，返回仍能恢复位置，只是允许重新加载内容。

### 2.2 性能目标

- 子会话时间线缓存有明确容量上限，不随页面使用时长无限增长。
- 恢复 N 个 turn 时，过程区状态上报只触发常数次快照写入，而不是 N 次。
- 快速滚动时不在每一帧扫描全部锚点。
- 流式输出期间降低缓存写入频率。
- 50 轮展开的极端场景下，不新增明显的主线程长任务。
- 不引入全量标签页保活。

## 3. 非目标

- 不把所有标签页切换为 `display: none` 常驻。
- 不缓存 iframe、PDF、视频、图片解码结果或 DOM 快照。
- 不把滚动位置写入 `localStorage` 或 IndexedDB。
- 不在第一阶段实现完整虚拟列表。
- 不改变现有返回栈、标签页关闭和其他标签类型的交互。
- 不为正常 8 轮场景引入复杂的可配置系统。

## 4. 当前实现与风险

### 4.1 滚动现场缓存

相关文件：

- `src/components/ActionView/workspaceTabScrollCache.ts`
- `src/components/ActionView/workspaceTabScrollRestore.ts`
- `src/components/Dialogue/AgentDetailPanel.tsx`

当前每个标签页只保存最新一份快照，包含：

- `scrollTop`
- `ratio`
- `atBottom`
- 锚点 ID 和偏移
- `visibleTurnCount`
- 过程区展开状态

这部分的单条数据很小，不是主要内存风险。

### 4.2 子会话时间线缓存

相关文件：

- `src/hooks/sessionTimelineCache.ts`
- `src/hooks/useSessionTimeline.ts`

当前每个 `childSessionId` 保存完整的 `history` 和 `runs` 引用。缓存没有容量上限，也没有 LRU 淘汰。

这是最优先处理的风险：用户在一个页面生命周期内打开很多长子 Agent 后，历史数据不会自动释放。

### 4.3 恢复大量 turn 时的重复快照

每个 `Dialogue` 首次挂载都会报告自己的过程区展开状态。每次报告当前都会立即写入一次滚动快照。

如果一次恢复 N 轮：

- 会产生最多 N 次快照写入。
- 每次写入都会扫描当前所有锚点。
- 总工作量接近 O(N²)。

8 轮时影响很小；50 轮时值得优化。

### 4.4 每帧锚点扫描

滚动事件已经使用 `requestAnimationFrame` 合并，但当前每帧仍可能执行：

- `querySelectorAll("[data-scroll-anchor-id]")`
- 对每个锚点读取 `getBoundingClientRect()`
- 复制过程区状态对象

默认 8 轮成本很低。展开到几十轮后，连续滚动可能产生不必要的布局读取。

### 4.5 流式状态写入

`useSessionTimeline` 当前在每次 state 变化时写时间线缓存。流式输出期间 state 变化频繁，虽然缓存写入不是深拷贝，但仍会造成 Map 写入和短生命周期对象分配。

## 5. 实施优先级

### P0：限制时间线缓存容量

目标：无论页面运行多久，时间线缓存都不会无限增长。

改动文件：

- `src/hooks/sessionTimelineCache.ts`
- `src/hooks/sessionTimelineCache.test.ts`

建议方案：

- 将缓存改为小型 LRU。
- 默认最多保留 12 个 `childSessionId`。
- `read` 命中后将该 key 移到最近使用位置。
- `write` 后如果超过上限，删除最久未使用的条目。
- 保留现有 `clearSessionTimelineCache` 接口。
- 常量导出给测试使用，但不增加运行时配置项。

行为影响：

- 被淘汰的子 Agent 再次打开时需要重新请求时间线。
- 滚动位置缓存不删除，因此内容加载完成后仍可恢复位置。

验收：

- 不同 `childSessionId` 的缓存继续隔离。
- 读取和写入的顺序都符合 LRU 规则。
- 超过容量后最旧条目被删除。
- 现有缓存测试全部通过。

### P0：合并过程区状态触发的快照写入

目标：批量恢复多个 turn 时，只写一次或少数几次快照。

改动文件：

- `src/components/Dialogue/AgentDetailPanel.tsx`

建议方案：

- 过程区状态变化时只更新 `processOpenByAnchorIdRef`。
- 标记“快照待刷新”。
- 使用一个 `requestAnimationFrame` 合并同一轮渲染中的所有写入。
- 组件卸载前强制 flush 一次。
- 滚动事件继续使用现有 rAF 节流，不与状态写入互相阻塞。

伪流程：

```text
processOpenChange
  -> 更新内存状态
  -> 如果已有待执行 flush，则不再调度
  -> 下一帧统一创建一次快照
```

验收：

- 首次挂载 50 轮时，状态上报不再产生 50 次快照扫描。
- 展开/折叠过程区后返回，状态仍然保持。
- 切换标签前最后一次状态变化不会丢失。

### P0：滚动时延迟计算锚点

目标：连续滚动时避免每帧扫描所有锚点。

改动文件：

- `src/components/ActionView/workspaceTabScrollRestore.ts`
- `src/components/Dialogue/AgentDetailPanel.tsx`
- `src/components/ActionView/workspaceTabScrollRestore.test.ts`

建议方案：

- 滚动过程中只记录便宜数据：`scrollTop`、比例、`scrollHeight`、`clientHeight`、`atBottom`。
- 用户停止滚动约 80～120ms 后，再计算锚点 ID 和偏移。
- 切走标签或卸载面板时，强制做一次完整快照。
- 保留“锚点优先、比例兜底”的恢复顺序。
- 不把锚点扫描改造成复杂索引；当前轮数上限下没有收益。

验收：

- 快速滚动时不会每帧调用 `getBoundingClientRect()` 遍历全部锚点。
- 停止滚动后缓存中能拿到完整锚点。
- 在停止滚动后立即切换标签，仍能恢复到最后位置。

### P1：降低流式时间线缓存写入频率

目标：减少高频 SSE 更新期间的缓存写入和 GC 压力。

改动文件：

- `src/hooks/useSessionTimeline.ts`
- 必要时新增小型缓存 flush 工具及测试

建议方案：

- 每次渲染只更新 `latestStateRef`。
- 缓存写入最多每 300～500ms 执行一次。
- 以下时机强制 flush：
  - run 进入终态；
  - sessionId 变化；
  - 组件卸载；
  - 用户主动 reload。
- 不在每个流式 item 更新时同步写 Map。

验收：

- 流式输出时缓存仍然能拿到接近最新的状态。
- 切走子 Agent 标签后返回，不会因为节流而显示明显旧内容。
- 缓存写入次数在合成流式测试中显著低于当前实现。

### P1：折叠状态下的内容懒渲染

目标：避免已折叠的过程时间线继续挂载大量内部内容。

改动文件：

- `src/components/Dialogue/index.tsx`
- 必要时调整 `CollapsibleContent` 的内部渲染

先确认：

- Radix Collapsible 在关闭态是否已经卸载 children。
- 如果已经卸载，则本项不做。
- 如果仍然保留大 DOM，则在关闭态不渲染 `AgentStepTimeline` 的昂贵子树。

验收：

- 折叠状态下不保留大量不可见工具卡片。
- 展开后内容完整。
- 过程的展开/折叠状态仍可缓存和恢复。

### P1：恢复后的短时间高度校正

目标：处理图片、字体、代码高亮晚加载导致的位置轻微漂移。

改动文件：

- `src/components/Dialogue/AgentDetailPanel.tsx`

建议方案：

- 恢复成功后启动 `ResizeObserver`。
- 最多观察 300～500ms。
- 内容高度变化时重新应用同一个恢复目标。
- 用户主动滚动或超时后立即断开 observer。

验收：

- 图片或字体晚加载时不会明显偏离原位置。
- 不会长时间与用户滚动竞争。
- 不产生永久 observer 或无限重试。

### P2：turn 级虚拟化

目标：只在真实测试证明必要时，降低超大子 Agent 的 DOM 数量。

触发条件：

- 50 轮展开后存在明显长任务或滚动掉帧。
- 且 P0/P1 优化完成后仍然存在。
- 或后续接口把单次历史上限从 50 轮继续提高。

候选方案：

- 使用项目已有的 `@tanstack/react-virtual`。
- 按 turn 做动态高度虚拟化。
- 保留锚点时需要同时保存虚拟 item key，而不是 DOM 下标。

暂不实施原因：

- 动态 Markdown、代码块和图片高度不稳定。
- 会显著增加滚动恢复、文本选择、浏览器查找和可访问性的复杂度。
- 当前默认只挂载 8 轮，尚无证据表明完整虚拟化是首要瓶颈。

## 6. 性能观测

增加开发环境下的轻量观测，不进入生产 UI：

- `sessionTimelineCache.size`
- 每个子会话的 run 数量和 timeline item 数量
- 单次恢复的锚点数量
- 单次快照创建耗时
- 长任务数量，基于 `PerformanceObserver({ entryTypes: ["longtask"] })`

建议用以下场景对比优化前后：

1. 默认 8 轮，连续滚动 10 秒。
2. 展开到 32 轮，连续滚动 10 秒。
3. 展开到 50 轮，且包含长工具输出。
4. 连续打开并切换 20 个不同子 Agent。
5. 流式输出期间持续滚动。

关注指标：

- 主线程长任务数量和最长耗时。
- 滚动期间平均帧间隔。
- 一次返回操作的恢复耗时。
- 快照写入次数。
- 缓存条目数量。
- 页面内存趋势。

## 7. 测试计划

### 7.1 单元测试

- LRU 容量、命中顺序和淘汰顺序。
- 关闭标签或 session 切换后的缓存清理。
- 快照合并在同一帧只执行一次。
- 快速滚动快照不包含多余锚点扫描。
- 停止滚动后的完整快照包含正确锚点。
- 现有锚点公式和比例兜底测试继续通过。

### 7.2 组件测试

- 大量 turn 首次挂载时，快照写入次数不超过固定上限。
- 过程区状态恢复仍正确。
- 用户主动滚动后，高度校正 observer 会停止。

## 8. 验收标准

- 普通 8 轮场景的交互与当前一致。
- 滚动到任意位置后切换标签并返回，位置仍然正确。
- 原本在底部时继续跟底。
- 展开更早轮次后返回，展开范围和过程区状态保持。
- 缓存条目数量有硬上限。
- 首次恢复 50 轮时，不产生 50 次重复完整快照。
- 连续滚动时锚点扫描被延迟到滚动空闲阶段。
- 流式输出期间缓存写入被节流。
- 页面刷新后不恢复旧位置。
- 关闭标签后重新打开，不恢复旧位置。

## 9. 推荐实施顺序

1. 时间线缓存 LRU。
2. 合并过程区状态触发的快照写入。
3. 滚动期间延迟锚点计算。
4. 流式时间线缓存节流和卸载 flush。
5. 折叠态内容懒渲染。
6. 短时间 ResizeObserver 校正。
7. 用性能数据判断是否需要 turn 级虚拟化。

第 1～4 项是本次性能优化的核心，改动范围可控，不改变用户可见行为。第 5～7 项根据真实测试结果决定是否继续。

## 10. 风险与回滚

| 风险 | 处理 |
| --- | --- |
| LRU 淘汰导致返回时需要重新加载 | 保留滚动快照；内容加载完成后继续恢复位置 |
| 快照合并导致最后一次状态变化丢失 | 组件卸载和切标签前强制 flush |
| 锚点延迟计算导致快速切换时没有锚点 | 卸载时同步执行一次完整快照 |
| 流式缓存节流导致返回时内容略旧 | 终态、卸载和主动 reload 时强制 flush |
| ResizeObserver 与用户滚动竞争 | 用户滚动后立即断开，并设置最大观察时长 |
| 虚拟化破坏滚动恢复 | 第一阶段不实施；只有性能数据明确需要时再单独设计 |
